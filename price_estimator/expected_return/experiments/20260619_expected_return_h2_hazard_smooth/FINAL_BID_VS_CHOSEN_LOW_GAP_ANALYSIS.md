# 最终下单价与窗口最低价 Gap 分析

## 1. 分析范围与口径

- 实验：`20260619_expected_return_h2_hazard_smooth`
- 数据源：`reports/predictions_validation.parquet`
- validation 时间窗：2026-04-11 00:20 UTC 至 2026-05-10 23:50 UTC
- 原始 accepted 样本：5,228
- 已提交订单（`bid > 0`）：2,825
- 其中 `chosen_low` 有效：2,808；缺失 17 条从 gap 分析中排除
- `bid`：策略输出的最终下单价格。
- `chosen_low`：从 `decision_time` 到结算前，所选下注侧 token 的最低成交价格。
- 绝对 gap：`bid - chosen_low`。正值表示下单价高于事后最低价，负值表示最低成交价没有下穿下单价。
- 相对 gap：`(bid - chosen_low) / (p_side - chosen_low)`。它表示从最低价到 `p_side` 的价差中，下单价已经向上走了多少比例。
- 相对 gap 只在 `p_side > chosen_low` 时有通常的几何含义。2,544 条满足该条件，264 条不满足；后者不进入比例汇总。
- 分桶为左闭右开 `[a, a+0.1)`；本实验最大 `bid=0.85`，因此最后一桶为 `[0.8, 0.9)`。

这里的 `chosen_low` 是事后窗口最低成交价，不代表当时该价格有足够盘口深度，也不代表可以精确成交在最低点。因此本文衡量的是报价相对事后最低打印的位置，不是可实现的订单执行滑点。

总体上，最终下单价比事后最低价平均高 0.162，中位数高 0.081。约 62% 的订单下单价高于最低打印，36% 的订单最低打印仍高于 bid，因此没有形成历史打印意义上的成交。

逐行相对 gap 的简单均值为 -184.0%，但该数字不可用于决策：当 `p_side` 与 `chosen_low` 非常接近时，分母接近零，少量负 gap 会产生极大的负比率（最小值 -1207.1）。中位数 50.9% 和聚合比率 59.7% 更稳定。

核心形态：

1. 订单高度集中在 `[0.5, 0.8)`，共 2,132 条，占有效订单的 75.9%。
2. 最大平均绝对 gap 出现在 `[0.5, 0.7)`：两桶均约 0.203–0.204，说明这一报价区域支付了最多的“高于事后最低价”的价格空间。
3. `[0.5, 0.7)` 的 gap 中位数为 0.10–0.15，相对 gap 中位数为 58.9%–64.9%。典型订单大约消耗了 `p_side` 到最低价价差的一半以上。
4. `[0.7, 0.8)` 的平均 gap 仍有 0.157，但中位数降至 0.030，分布明显右偏：多数订单贴近最低价，少数大 gap 抬高均值。
5. `[0.8, 0.9)` 的平均和中位 gap 已转负，只有 24.2% 的订单 `bid > chosen_low`。高报价并不自动意味着更容易被最低打印穿过，因为这一桶对应的 token 市场价格本身也高。
6. 低 bid 桶样本很少：`bid < 0.3` 仅 116 条。其负 gap 不能据此解释为策略更优，主要含义是这些深价订单多数没有被市场最低打印触达。

`printed filled` 子集的 gap 中位数为 0.294，相对 gap 中位数为 69.3%；P25/P75 为 44.6%/82.6%，P10/P90 为 21.6%/87.8%。也就是说，在实际最低打印穿过 bid 的订单中，策略报价通常位于最低价到 `p_side` 距离的较高位置。

方向错误订单的 gap 明显更大，这是标签机制的机械结果，不应解释成模型发现了更好的价格：下注侧最终归零时，其 token 在结算前通常会交易到很低，`chosen_low` 均值仅 0.057。因此 wrong 子集的 gap 和相对 gap 会自然偏高。判断报价效率时，应同时查看 correct 子集；该子集平均 gap 只有 0.046，中位数为 0，printed-fill 率为 51.6%。

UP 与 DOWN 的 gap 分布非常接近，均值仅相差 0.003，中位数基本相同，没有明显 side 级报价偏差。

## 5. 结论

- 对全部 validation 已提交且最低价有效的订单，最终下单价相对事后最低价的典型 gap 为 0.081，平均为 0.162。
- 在 `p_side > chosen_low` 的可解释样本中，最终报价位于“最低价到 p_side”区间的中位位置 50.9%；按总价差加权后为 59.7%。
- 真正被最低打印穿过的订单，比例明显更高：中位数 69.3%，聚合 71.7%。这说明成交订单整体支付了 `p_side` 与事后最低价之间约七成的价差。
- 报价成本最突出的区域是 `bid ∈ [0.5, 0.7)`；该区域覆盖订单最多，平均绝对 gap 也最高，是后续测试降低 bid、增加 offset 或调整 EV gate 时最值得优先观察的区间。
- 不能用全部样本的相对 gap 简单均值做优化目标；接近零的分母会使其失真。建议持续报告比例中位数、聚合比例、有效分母样本数，并按 correct / wrong 与 printed-fill 状态分层。

本分析不改变实验结果或交易策略，也不声称提升 validation `sum_pnl`；它只描述现有最终报价相对事后最低成交价的位置。
