# Direct Policy PnL 缺口深度分析：为什么 oracle 3224，实际只有 137

日期：2026-07-09
分析对象：
- `.arbor/sessions/20260708_direct_policy_market_order`（V1，best node `DP2_direct_policy_regret_ce` = **137.08**）
- `.arbor/sessions/20260708_direct_policy_loss_price_aware`（V2，loss + price-aware 改造）

数据来源：V1 `DP2_direct_policy_regret_ce/predictions_btest.parquet`（B_test 冻结月，7468 行，逐笔可复算）。V2 各 node 目前只落了 `REPORT.md` + `config_used.yaml`，逐笔 `metrics_*.json / predictions_btest.parquet / confusion_btest.csv` **没有写出/回传**，所以定量拆解全部基于 V1 DP2 的 parquet，V2 只用其 summary 数字做对照。

## 0. 一句话结论

> **单笔期望收益 = 方向命中率 − 平均买入价**（`E[pnl/trade] = accuracy − avg_entry_price`）。
> DP2 = `0.6327 − 0.6136 = +0.0191`；oracle = `1.0 − 0.563 = +0.437`。
> **3224 → 137 的缺口几乎 100% 来自方向命中率不足**，而不是 loss 函数、决策层或下注价格。市场价 `m` 本身已经是一个高度有效的概率估计，模型相对市场的边际优势只有约 **+2.5 个百分点命中率**，且只存在于 `price ≥ 0.35` 区间。

因此：**能大幅提高 PnL 的唯一支配性杠杆是「相对市场更准的方向信号」**（正交特征 / 更好的 base model）。V2 花在 loss 重塑和 price-aware 决策上的全部改造，最好也只从 137 走到 147，多个 node 反而更差——这恰好从反面证明了瓶颈不在目标函数/决策层。

## 2. 核心诊断：为什么 oracle 3224 但实际只有 137

下面全部基于 V1 DP2 的 7468 行 B_test 逐笔数据。

### 2.1 支配性恒等式

市价单机制下，单笔盈亏只有两种：
```
买对（chosen 侧最终赢） pnl = 1 − m_chosen
买错（chosen 侧最终输） pnl =   − m_chosen
```
对所有成交求和并整理：
```
sum_pnl = Σ (y_chosen − m_chosen)
E[pnl/trade] = P(chosen 侧赢) − E[m_chosen] = accuracy − avg_entry_price
```

代入实际数字（逐笔可复算，误差 < 1e-4）：

| 主体 | 命中率 accuracy | 平均买入价 avg_entry | 单笔 E[pnl] | 总 PnL |
|---|---:|---:|---:|---:|
| **DP2 模型** | 0.6327 | 0.6136 | **+0.0191** | **137.08** |
| **Oracle** | 1.0000 | 0.5630 | **+0.4370** | **3224.24** |

**结论：oracle 的优势 100% 来自「命中率 = 1.0」。** 它并没有买得更便宜（oracle 平均买入价 0.563，模型 0.614，只差 5 个点），它只是**每次都买中赢的那一侧**。模型的单笔期望 0.0191 ≈ 0，几乎在盈亏平衡线上。

### 2.2 盈亏不对称：为什么 63% 命中率还几乎不赚钱

| | 平均值 |
|---|---:|
| 买对时平均盈利 | **+0.3551** |
| 买错时平均亏损 | **−0.5599** |
| 盈亏平衡命中率 = 0.5599 / (0.3551+0.5599) | **0.6119** |
| 实际命中率 | 0.6327 |
| **实际 − 平衡（安全垫）** | **仅 +2.1 pp** |

亏损（0.56）比盈利（0.355）大 **1.58 倍**，原因是模型倾向买**贵的一侧（favorite）**：
- 买对时平均买入价 = **0.6449**（贵的赢家，赚 0.355）
- 买错时平均买入价 = **0.5599**（中等价位输掉，亏 0.560）

于是命中率必须 > 61.2% 才不亏，模型 63.3% 只高出 2.1 个点 → 净利被压到接近 0。**这就是为什么 win_sum 1616 与 loss_sum −1479 几乎抵消，只剩 137。**

### 2.3 市场是有效的（最关键的证据）

把「模型选中侧的市场价 `m_chosen`」当作市场隐含胜率，对比模型的实际胜率：

| chosen 侧价格桶 | n | 平均市场价 | 模型实际胜率 | 边际 edge = 胜率 − 价格 |
|---|---:|---:|---:|---:|
| (0.20,0.30] | 79 | ~0.27 | ~0.22 | **−0.05（负）** |
| (0.30,0.35] | 150 | 0.333 | 0.293 | **−0.040（负）** |
| (0.35,0.45] | 600 | ~0.40 | ~0.44 | +0.04 |
| (0.45,0.55] | 1441 | ~0.50 | ~0.52 | +0.02 |
| (0.55,0.65] | 1908 | ~0.60 | ~0.62 | +0.02 |
| (0.65,0.75] | 1708 | ~0.70 | ~0.71 | +0.01 |
| (0.75,0.85] | 987 | ~0.79 | ~0.82 | +0.03 |
| (0.85,1.00] | 309 | ~0.89 | ~0.92 | +0.03 |
| **整体** | 7193 | **0.6136** | **0.6327** | **+0.0191** |

**每一个价格桶里，模型的实际胜率都几乎等于市场价。** 这说明：
- 市场价 `m` 本身就是一个校准良好的胜率估计，**模型相对市场的信息增量极小（平均只有 ~+2 pp）**。
- 在便宜侧（价格 < 0.35），模型 edge 甚至是**负的**——模型下注冷门时，比市场还差。
- +137 的全部来源，是价格 ≥ 0.35 区间那点薄薄的 +2~4 pp edge 累加出来的。

### 2.4 oracle 的价值藏在「冷门赢家」，而模型抓不到

按「赢家一侧的价格」拆 oracle 的 3224：

| 赢家侧价格 | n | oracle_pnl | 占比 | 单笔均值 |
|---|---:|---:|---:|---:|
| (0.0,0.3] | 509 | 384.7 | 11.9% | 0.756 |
| (0.3,0.4] | 871 | 558.3 | 17.3% | 0.641 |
| (0.4,0.5] | 1355 | 735.6 | 22.8% | 0.543 |
| (0.5,0.6] | 1556 | 692.2 | 21.5% | 0.445 |
| (0.6,0.7] | 1464 | 507.7 | 15.7% | 0.347 |
| (0.7,0.8] | 1088 | 270.3 | 8.4% | 0.248 |
| (0.8,1.0] | 535 | 75.4 | 2.3% | 0.141 |

**约 52% 的 oracle 价值来自「赢家价格 < 0.5」的冷门翻盘**，单笔价值最高（0.54–0.76）。但这正是模型**完全抓不到**的部分：当模型去买便宜侧（chosen_m < 0.4）时，命中率只有 21–36%，是净亏的（见 2.3）。要拿到这块价值，需要能识别「意外/冷门」的正交信号，而不是价格或置信度技巧。

### 2.5 混淆矩阵（action × oracle_action）

计数：
```
oracle→        BUY_NO  BUY_YES  NO_TRADE
BUY_NO          2218     1386        2
BUY_YES         1247     2333        7
NO_TRADE         106       88       81
```
逐笔 PnL 求和：
```
oracle→        BUY_NO   BUY_YES  NO_TRADE
BUY_NO         +824.1   −759.9    −1.0
BUY_YES        −714.8   +792.1    −3.4
```
- 买对：824.1 + 792.1 = **+1616.2**
- 错边：−759.9 − 714.8 = **−1474.7**（共 1386+1247 = **2633 笔错边**）
- 净 = 137。错边交易吃掉了几乎全部盈利。

### 2.6 为什么这里 acc 0.63，而 deploy 方向模型是 0.70+（不矛盾）

这是一个 universe / 分母 的差异，不是模型变差了。

**这些实验用的是哪个模型？**
- `DP1_static_ev_baseline` 直接用 **deploy 方向模型的 `p_up` 输出**（`score_column: p_up`）——这一支就是 deploy 模型本身。
- `DP2/DP3/DP5/DP6` 是在 **deploy 的 569 列特征上重新训练的 3-class XGBoost**（label = oracle_action，regret/soft 加权），不是 deploy 模型本身，但吃的是同一套特征（DP5/DP6 另加了几个 research-only 价格特征）。`DP4` 是叠在 DP5 之上的决策层。

**为什么 acc 掉到 0.63：**
- deploy 报的 0.70+ 是在 **accepted 子集**上——只有 `p_up` 越过接受阈值（`t_up=0.579 / t_down=0.431`，约 70% coverage）的样本才算，被拒的 ~30% 恰好是 `p_up≈0.5` 的低置信、近抛硬币的难样本。
- 这几个直接策略实验**刻意不使用接受阈值**（v2 计划：「不使用方向分类器的 accepted threshold / `t_up` / `t_down` 做样本筛选，所有有合法 1:08 市价的行都进入评估」），trade_rate ≈ 96%，把那 30% 难中间段全放了进来，于是命中率被拉到 0.63。
- **数据验证**（DP2 逐笔，按 `|pi_yes−pi_no|` 置信度取子集，模拟接受阈值）：

  | 取置信度 top-k | 笔数 | accuracy | 平均买入价 | edge=acc−price | sum_pnl |
  |---:|---:|---:|---:|---:|---:|
  | 30% | 2157 | 0.7515 | 0.7256 | 0.0259 | 55.86 |
  | 50% | 3596 | **0.7041** | 0.6840 | 0.0201 | 72.32 |
  | 70% | 5035 | 0.6717 | 0.6529 | 0.0188 | 94.83 |
  | 100%（全 universe） | 7193 | 0.6327 | 0.6136 | 0.0191 | **137.08** |

- 取最有把握的一半，accuracy 就回到 **0.704**（≈ deploy 的 0.707）——**证明这是同一个信号在不同 universe 上的两个读数，不是两个模型。**

**关键含义（反而印证主结论）**：注意上表——命中率从 0.63 抬到 0.75 的同时，**平均买入价从 0.61 同步涨到 0.73**，因为「有把握」= 贵的 favorite。于是 `edge = acc − price` 始终锁在 ~0.02，`sum_pnl` 不升反降（137 → 72，因为交易笔数变少）。也就是说：**deploy 那 0.70 的高命中率早已被高市场价「定价」进去了**，把它筛出来单独交易并不会带来更多 PnL。这正是「接受阈值 / 弃单 / 选择性下注不是杠杆」的根源，也说明真正要的是**相对市场价的净 edge**（§4 杠杆 1），而不是更高的原始 accuracy。

## 3. 哪些「看起来能改」的方向其实不是杠杆

这些都被 V1/V2 的数据直接证伪，写下来避免重复踩坑：

| 尝试 | 证据 | 为什么无效 |
|---|---|---|
| **重塑 loss（soft reward / regret 加权 / direct PnL objective）** | V2 DP2/DP3/DP5 = 147/143/86，`wrong_side_loss_abs` 纹丝不动 | 同一套特征下，模型胜率 ≈ 市场价这个事实不因 loss 而改变 |
| **price-aware 决策（utility = s−m−τ，argmax utility）** | V2 DP4 = 59、DP5 = 86，**低于**朴素 DP2 137 | 市场有效 → 按价格倾斜决策只会把注更多压到贵 favorite（单笔 edge 更薄），或过拟合 |
| **置信度弃单（按 \|pi_yes−pi_no\| 取 top-k%）** | top-10% 置信度命中率 82.6%，但单笔仅 0.029；各置信度十分位单笔均值只在 0.012~0.029 间 | 置信度 = 价格极端度 = favorite；弃单只是砍掉笔数，总 PnL 反而下降（砍掉一半只剩 ~72） |
| **只买便宜侧（想吃冷门价值）** | chosen_m ≤ 0.4 的 497 笔合计 **−6.3**，命中率 33% | 模型无法预测冷门，买便宜侧 = 负 edge |
| **限价单压低买入价** | 参见 `docs/gc_market_stop_why_market_order_won_20260706.md`：market 122.6 vs limit 45.4 | 便宜的成交价是「信息」不是「折扣」——价格跌到你的低买价，正是因为市场在抛你这一侧（adverse selection） |

**共同本质**：在「模型胜率 ≈ 市场价」的前提下，任何只在**目标函数 / 决策规则 / 下注价格 / 弃单阈值**上做文章的改造，都在同一个 ~0.03 单笔 edge 天花板下打转，无法放大 PnL。

## 4. 大幅提高 PnL 的方案（按杠杆排序）

### 杠杆 1（支配性，其余都是零头）：相对市场更准的方向信号

固定这 7193 笔、保持买入价分布不变，只改变命中率的反事实：

| 命中率 | 估计 sum_pnl | 相对 137 |
|---:|---:|---:|
| 0.6327（现状） | 137 | 1.0× |
| 0.65 | 251 | 1.8× |
| 0.68 | 448 | 3.3× |
| 0.70 | 580 | 4.2× |
| 0.72 | 712 | 5.2× |
| 0.75 | 909 | 6.6× |
| 0.80 | 1238 | 9.0× |
| 0.90 | 1896 | 13.8× |
| 1.00 | 2554 | oracle（此子集） |

**命中率每 +1 pp ≈ +65 PnL。** 这是唯一能把 137 拉到几百上千的路径。

关键点：目标不是「更高的原始准确率」，而是「**在给定市场价条件下，胜率超过市场价**」——即 2.3 表里的 `edge = 胜率 − 价格` 要显著为正。当前只有 ~+2 pp。可行方向：
- **正交微结构特征**（决策时刻的 order-flow 失衡、order-book depth/imbalance、BTC 现货 microstructure、短周期动量/波动状态），这些是市场价里**尚未完全定价**的信息。判据：加入后 2.3 表里某价格桶的 `edge` 是否稳定放大。
- **base 方向模型本身的重训 / 校准**：当前 `p_up` 在低价侧是负 edge（欠校准），至少先把 <0.35 区间的系统性偏差修正掉。
- 现实预期：repo 历史（`crypto_engine_notes.md`）显示原始方向准确率在当前特征包下**上限约 0.70**。即便只到 0.68–0.70，也是 3–4× PnL（448–580）。这应是本条线的首要 KPI，而不是再去调 loss。

> 换句话说：**下一轮的主实验应该是「特征 / 方向模型」实验，而不是「策略 / 决策」实验。** 用 `edge = 实测胜率 − 市场价（分价格桶）` 作为主诊断指标，只要它能从 +0.02 稳定抬到 +0.05，PnL 就能到 3–4 倍。

### 杠杆 2（增量，几十的量级）：EV 门控 + 砍负 edge 区 + 按 edge 定注

不改方向信号，只做「把已有的薄 edge 用干净」：
1. **砍掉负 edge 区**：不下注 `chosen_m < 0.35`（2.3 表中 edge 为负的区间，约 229 笔）。注意阈值要卡在 0.35 而非 0.45——(0.35,0.45] 是**正** edge 且是最赚的桶之一，砍过头（<0.45）反而把 PnL 从 137 降到 122。
2. **校准后的 EV 门控**：只在 `calibrated_prob − m > margin` 时下注，`margin` 用来抵消 adverse selection（不是原始 `pi`，要先做 isotonic/Platt 校准）。
3. **按 edge 定注（Kelly / edge-proportional sizing）**：单笔 edge 平均 0.03 但方差大，在**固定资金**下把仓位按 `(prob − price)` 比例分配，可以在不改命中率的情况下抬高资金回报率（注意：当前 sum_pnl 指标是「每笔 1 单位」，这条要在允许变仓位的口径下才体现）。

预期量级：合计**几十** PnL，受 ~0.03 单笔 edge 天花板限制，无法单独把结果翻倍。定位是「杠杆 1 落地前的低风险 hygiene」，不是主攻方向。

### 杠杆 3（高天花板，但依赖杠杆 1）：定向攻「冷门赢家」价值

2.4 显示 52% 的 oracle 价值在「赢家价 < 0.5」的翻盘里，单笔 0.54–0.76。抓住哪怕一部分，单笔收益是当前的 15–25 倍。但这**必须**有一个能识别「意外/反转」的正交信号（本质仍是杠杆 1 的一种特化），当前特征做不到。可作为杠杆 1 里的一个专门子任务：单独训练一个「surprise / reversal」检测头，只在它高置信时才去碰便宜侧。

### 明确不再投入的方向
- 继续调 loss（soft/regret/direct-PnL objective）——V2 已证伪。
- price-aware argmax / utility 决策层——V2 DP4/DP5 反而更差。
- 纯置信度弃单、只买便宜侧、限价压价——全部被数据证伪。

## 5. 建议的下一轮实验设计（窄目标）

新 session 建议：`.arbor/sessions/20260709_direction_edge_over_market`

1. **主诊断指标换成 `edge = 实测胜率 − 市场隐含价（分价格桶）`**，而不是只看 sum_pnl。sum_pnl 是滞后结果，edge 才是可归因的杠杆。
2. **F1 正交特征包实验**：在现有 base 之上，逐个加入 order-flow 失衡 / book imbalance / BTC 现货微结构 / 短周期波动状态，看 `edge` 曲线是否在中高价桶稳定抬升。每个特征包只用 w1–w4 选，w5–w6 做 holdout，B_test 每个 named node 记一次。
